# 01. 需求说明

## 1. 项目背景

Shinkou 是一个面向研发团队的需求变更影响分析平台。它解决的核心问题是：当产品、业务或技术负责人提出一个需求变更时，研发团队需要快速判断这个变更会影响哪些模块、哪些文件、哪些接口、哪些数据表，以及它会带来哪些风险和任务。

传统流程通常依赖人工经验：

```text
需求评审
→ 开发人员凭经验搜索代码
→ 口头判断影响范围
→ 手工拆任务
→ 手工写风险点和测试建议
→ 后续开发过程中不断补漏
```

这个流程的问题是：

```text
影响范围容易漏
跨模块关系难以追踪
评审结论难以审计
任务拆分不稳定
新人难以理解历史系统
需求变更成本不可控
```

Shinkou 希望把这类判断过程结构化、可追踪、可沉淀。

## 2. 产品定位

Shinkou 不是 IDE 编码助手，不直接替代 Cursor、Claude Code、GitHub Copilot 等工具。

Shinkou 更关注：

```text
需求会影响哪些模块
哪些文件、接口、页面、数据表可能要改
这个变更有哪些技术风险
需要补充哪些测试场景
任务应该如何拆分
分析过程调用了哪些工具和文件
如何生成可审计的分析报告
```

适用场景：

```text
需求评审前的影响范围预分析
技术方案设计前的代码探索
复杂系统新人接手时的上下文理解
变更风险评估
研发任务拆解
测试范围确认
研发知识沉淀和复盘
```

不适用场景：

```text
直接替用户修改代码并提交
替代 IDE 内联补全
实时结对编程
无代码仓库上下文的泛泛问答
```

## 3. 用户与角色

### 3.1 平台用户

| 用户 | 主要诉求 |
| ---- | -------- |
| 研发负责人 | 快速判断需求影响范围、风险和任务规模 |
| 后端开发 | 找到受影响服务、接口、数据表和核心代码 |
| 前端开发 | 找到受影响页面、状态管理和接口调用 |
| 测试人员 | 根据影响范围生成测试关注点 |
| 产品 / 项目经理 | 理解变更成本、风险和交付任务 |
| 新成员 | 快速理解项目结构和业务流程 |

### 3.2 工作区角色

MVP 建议支持：

| 角色 | 说明 |
| ---- | ---- |
| `OWNER` | 工作区所有者，最高权限 |
| `ADMIN` | 管理员，可邀请成员、管理项目 |
| `MEMBER` | 普通成员，可查看项目、发起分析 |

后续可扩展：

| 角色 | 说明 |
| ---- | ---- |
| `VIEWER` | 只读成员 |
| `AUDITOR` | 审计成员 |

## 4. 核心业务概念

### 4.1 用户

用户通过企业邮箱登录。平台不开放普通注册，用户必须通过邀请链接激活账号。

### 4.2 工作区

工作区表示一个团队、部门、项目群或组织空间。所有项目、文件、分析、任务和报告都归属于某个工作区。

### 4.3 项目

项目表示一个代码库或业务系统。MVP 阶段通过 ZIP 上传项目代码，后续支持 Git 仓库接入。

### 4.4 项目文件

项目上传后，后端解压、扫描并保存文件索引。文件索引用于文件树展示、关键词搜索、读取文件片段和 AI 分析。

### 4.5 分析会话

用户输入一个需求后，系统创建一次 Agent 分析会话。分析会话记录需求文本、分析状态、总结、影响文件、风险点、任务草稿和工具调用轨迹。

### 4.6 工具调用

Agent 在分析过程中会调用工具，例如：

```text
列出项目文件树
搜索关键词
读取文件片段
生成影响文件
生成风险点
生成任务草稿
生成报告
```

这些调用需要记录下来，便于前端展示过程和后续审计。

## 5. MVP 目标

Version 0.1 的目标链路：

```text
邀请激活账号
→ 登录
→ 选择工作区
→ 创建项目
→ 上传项目 ZIP
→ 扫描项目文件
→ 建立文件索引
→ 输入需求
→ Agent 搜索代码并读取文件片段
→ 生成影响分析
→ 生成风险点
→ 生成任务草稿
→ 展示工具调用轨迹
→ 查看报告
```

MVP 不追求完整自动开发，而是先完成“需求影响分析闭环”。

## 6. 功能需求

### 6.1 认证与激活

需求：

```text
用户只能通过企业邮箱和密码登录
用户必须通过邀请链接激活账号
不开放普通注册
登录后返回用户加入的工作区列表
如果只有一个工作区，可直接进入
如果有多个工作区，进入工作区选择页
退出登录需要通知后端并清理会话
```

安全目标：

```text
前端不保存 accessToken 到 localStorage
后端通过 HttpOnly Cookie 保存登录态
前端请求使用 credentials / withCredentials
后端负责 Cookie 签发、认证和清除
```

当前实现说明：

```text
前端已按 Cookie 会话方式改造。
后端当前仍主要是 Bearer JWT 认证模式，需要补齐 Cookie 签发和读取。
```

### 6.2 工作区

需求：

```text
用户登录后可以选择工作区
工作区隔离项目、成员、分析和报告
所有业务接口带 workspaceId
用户只能访问自己是 ACTIVE 成员的工作区
```

后续增强：

```text
工作区归档
成员管理
角色修改
邀请管理
主动退出工作区
```

### 6.3 项目管理

需求：

```text
在工作区下创建项目
项目 code 在同一工作区内唯一
项目可查看、更新、删除或归档
项目列表支持按状态和关键词筛选
```

创建项目字段：

```text
name
code
description
```

项目状态：

```text
ACTIVE
ARCHIVED
DELETED
```

### 6.4 文件管理

需求：

```text
上传项目 ZIP
后端安全解压
过滤无关目录和危险路径
扫描项目文件
保存文件索引
展示文件树
展示文件列表
支持关键词搜索
支持读取文件内容或指定行
```

安全要求：

```text
禁止路径穿越
限制 ZIP 大小
限制单文件大小
过滤 .git、node_modules、target、build、dist 等目录
读取文件只能访问项目根目录内的相对路径
```

### 6.5 代码探索

需求：

```text
提供类 IDE 的代码浏览体验
支持文件树、搜索、标签页、代码预览
支持 AI 建议或分析结果侧栏
支持工具调用轨迹和终端样式展示
```

MVP 前端可以使用 mock 数据展示交互；后续逐步接入真实文件接口。

### 6.6 需求影响分析

需求：

```text
用户输入自然语言需求
后端创建分析会话
Agent 理解需求并提取关键词
Agent 搜索文件内容
Agent 读取关键文件片段
Agent 生成影响文件、风险点和任务草稿
前端展示分析结果和执行轨迹
```

输入约束：

```text
需求文本不能为空
建议限制最大长度，例如 2000 字符
```

输出内容：

```text
分析总结
影响文件列表
影响原因
影响行号
置信度
风险点
任务草稿
工具调用步骤
```

### 6.7 任务看板

需求：

```text
展示 AI 生成的任务草稿
支持任务状态流转
支持按状态、优先级、来源筛选
支持看板视图
```

任务状态建议：

```text
CONFIRMING
TODO
IN_PROGRESS
DONE
```

任务草稿状态建议：

```text
DRAFT
ACCEPTED
REJECTED
CONVERTED
```

### 6.8 报告中心

需求：

```text
展示分析报告列表
支持按报告类型筛选
支持 Markdown 预览
支持下载 PDF 或 Markdown
支持删除报告
```

报告内容建议：

```text
需求原文
分析总结
影响文件
风险点
任务拆解
测试建议
工具调用摘要
生成时间
版本信息
```

### 6.9 模型与工具配置

需求：

```text
配置聊天模型
配置 Embedding 模型
配置 Reranker 模型
配置 Agent 可调用工具
配置工具权限等级
配置工具是否需要人工确认

```

工具权限建议：

```text
READ

```

## 7. 非功能需求

### 7.1 安全

```text
前端不存储明文 token
后端使用 HttpOnly Cookie 保存登录态
密码使用 BCrypt 等强哈希算法
关键写操作校验权限
业务接口校验 workspace 成员关系
文件读取防止路径穿越
上传文件限制大小和类型
生产环境使用 HTTPS
Cookie 设置 Secure 和 SameSite
```

### 7.2 可审计

建议记录：

```text
登录成功 / 失败
激活账号
退出登录
创建邀请
创建项目
上传 ZIP
发起分析
生成报告
删除项目
成员变更
```

### 7.3 可观测

建议记录：

```text
请求 ID
用户 ID
工作区 ID
项目 ID
Agent sessionId
工具调用耗时
AI 服务响应时间
错误码和错误消息
```

### 7.4 性能

MVP 目标：

```text
项目列表、文件列表普通查询 < 1s
关键词搜索在中小项目内 < 3s
AI 分析允许异步执行
长耗时任务需要前端展示状态
```

### 7.5 可扩展

系统需要为以下能力预留扩展：

```text
Git 仓库接入
PR Diff 分析
RAG 语义检索
多模型配置
多智能体编排
审计日志
企业 SSO
项目级权限
```

## 8. 关键业务流程

### 8.1 激活账号

```text
用户打开邀请链接
→ 前端读取 token
→ 查询邀请信息
→ 用户设置密码
→ 后端校验邀请和密码
→ 创建或激活用户
→ 加入工作区
→ 写入登录 Cookie
→ 返回用户和工作区信息
```

### 8.2 登录

```text
用户输入企业邮箱和密码
→ 后端校验密码和账号状态
→ 查询用户工作区
→ 创建登录会话
→ 写入 HttpOnly Cookie
→ 前端根据工作区数量决定跳转
```

### 8.3 创建项目并上传代码

```text
用户选择工作区
→ 创建项目
→ 上传 ZIP
→ 后端保存并安全解压
→ 扫描文件
→ 写入 project_files
→ 更新项目 fileCount
→ 前端展示文件树和文件列表
```

### 8.4 发起影响分析

```text
用户输入需求
→ 创建 agent_session
→ Agent 提取关键词
→ 搜索项目文件
→ 读取关键片段
→ 生成影响文件、风险和任务草稿
→ 写入分析结果表
→ 前端展示分析结果和执行轨迹
```

## 9. 验收标准

MVP 完成标准：

```text
用户可通过邀请激活并登录
用户可选择工作区
用户可创建项目
用户可上传 ZIP 并看到文件列表
用户可搜索代码内容
用户可输入需求并得到影响分析结果
用户可看到 Agent 工具调用轨迹
用户可看到风险点和任务草稿
用户可退出登录，后端会话失效
```

```text

开发流程以 docs/05-development.md 为准
```
